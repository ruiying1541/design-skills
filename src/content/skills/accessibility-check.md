## 为什么可访问性很重要？

- 全球约 **15%** 的人口存在某种形式的残障（WHO 数据）
- 可访问性好的产品对**所有人**都更易用（强光下看手机、单手操作、嘈杂环境等）
- 许多国家和地区的法规要求数字产品达到 WCAG AA 级别
- 可访问性问题在设计阶段修复的成本，是开发后修复的 **1/10**

---

## WCAG 三个合规等级

| 等级 | 要求 | 适用场景 |
|------|------|---------|
| A    | 最低要求 | 不推荐只做到 A |
| **AA** | **推荐标准** | **大多数产品应达到此标准** |
| AAA | 最高要求 | 政府/医疗/教育类产品 |

## 色彩对比度（最常见问题）

WCAG AA 对比度要求：

| 场景 | 最低对比度 |
|------|---------|
| 正常文本（< 18px） | **4.5 : 1** |
| 大文本（≥ 18px 常规 / ≥ 14px 加粗） | **3 : 1** |
| UI 组件、图标、图表 | **3 : 1** |
| 装饰性元素 | 无要求 |

### 常见错误案例

```
❌ 灰色文字 #9CA3AF 在白色背景（对比度 2.7:1）— 不达标
✅ 灰色文字 #6B7280 在白色背景（对比度 4.6:1）— AA 通过

❌ 白色文字在浅黄色按钮 #FCD34D（对比度 1.5:1）— 不达标  
✅ 深色文字 #1F2937 在浅黄色按钮（对比度 11:1）— 通过
```

### 如何检测

1. **Figma 插件**：Contrast 、A11y Annotation Kit
2. **在线工具**：[Contrast Checker](https://webaim.org/resources/contrastchecker/)
3. **代码检查**：axe DevTools Chrome 插件（自动扫描页面）

## 触摸目标尺寸

移动端可触摸区域最小应为 **44×44pt**（iOS HIG 要求），Android 建议 **48×48dp**。

即使图标只有 24px，其可触摸区域也应扩展到 44px：

```css
/* 正确做法：用 padding 扩大点击区域 */
.icon-button {
  padding: 10px;  /* 24px 图标 + 10px×2 = 44px */
}
```

## 键盘可访问性

所有可交互元素必须：

- [ ] 可以用 Tab 键聚焦
- [ ] 聚焦状态有清晰的视觉反馈（不能只靠颜色区分）
- [ ] 可以用 Enter/Space 触发
- [ ] 焦点顺序符合视觉阅读顺序
- [ ] 弹窗打开后焦点锁定在弹窗内，关闭后焦点返回触发元素

---

## 颜色非唯一信息传递

**不要**只用颜色来传递状态：

```
❌ 错误：红色 = 错误，绿色 = 成功（色盲用户无法区分）
✅ 正确：红色图标 + "输入格式错误" 文字提示
✅ 正确：绿色 + ✓ 图标 + "保存成功" 文字
```

## 图片替代文字（Alt Text）

```html
<!-- 有含义的图片 -->
<img src="profile.jpg" alt="用户张三的头像">

<!-- 装饰性图片（屏幕阅读器跳过） -->
<img src="decoration.png" alt="" role="presentation">

<!-- 图标按钮 -->
<button aria-label="删除这条评论">
  <svg>...</svg>
</button>
```

## 可访问性检查 Checklist

### 颜色与视觉
- [ ] 正文文字对比度 ≥ 4.5:1
- [ ] 大文字对比度 ≥ 3:1
- [ ] UI 组件对比度 ≥ 3:1
- [ ] 不仅凭颜色传递信息

### 操作与交互
- [ ] 所有交互元素可键盘聚焦
- [ ] 聚焦状态有明显视觉反馈
- [ ] 触摸目标 ≥ 44×44pt
- [ ] 链接/按钮描述文字有意义（非「点击这里」）

### 内容
- [ ] 所有图片有 alt 文字（装饰图为空 alt）
- [ ] 视频有字幕或文字说明
- [ ] 页面标题唯一且有描述性
- [ ] 表单 input 有对应 label
